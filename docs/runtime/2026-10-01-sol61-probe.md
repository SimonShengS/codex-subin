## Method and evidence

Each short probe selected its registered `agent_type` with `fork_turns="none"`, without model or effort overrides. Probes were dispatched in batches of at most three and instructed to use no tools, edits, or delegation, then return immediately. All ten probes completed.

The child-facing interface did not expose model, effort, or role to the agents themselves, so their replies correctly marked those fields unobservable. Root independently read host-side rollout metadata: the spawned session's `session_meta.agent_role` established the role, and its runtime `turn_context` established model, effort, and protocol. Parent linkage associated each record with this run; copied ancestor metadata was not treated as the spawned session's identity. Filenames, task names, task paths, configuration expectations, and child self-reports were not used to infer roles or model selection. Private paths, identifiers, and raw logs are omitted.

## Limits

This confirms named routing, actual model and effort, and minimal execution in one installation. The interface did not expose an authoritative originating TOML path; it therefore does not independently prove which filesystem path supplied each role definition.

It does not compare quality, discovery completeness, financial-thesis accuracy, speed, or token cost. It does not test sustained load, maximum simultaneous concurrency, nested delegation, or Efficient's optional Luna/max worker. Historical GPT-5.6 benchmark results are not evidence for this GPT-6.1 mapping.
